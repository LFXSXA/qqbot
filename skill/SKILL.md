# 从聊天记录蒸馏一个 AI 伙伴

> 核心原则：**人设不是写出来的，是从语料里量出来的。**

大多数人做 AI 人格的方式是「我希望她温柔、可爱、偶尔撒娇」，结果出来一个 AI 味的客服。
这套流程换来的是：先统计这个人在真实对话里的**句长、结尾字、语气词、称呼、情绪表达方式**，
再把这些数字写成规则，配上**原话**做示例——模型才有得可依。

---

## 0. 先确认三件事

| 问题 | 为什么要问 |
|---|---|
| 数据在哪？ | 微信 / QQ / TG / 导出的 txt，格式决定用哪个解析器 |
| 关系是什么？ | 恋人 / 朋友 / 自己 / 已故亲人——决定语气边界和「修复层」怎么写 |
| 目的是什么？ | 复刻原样 / **修正成更好的样子** / 只是想要那个说话风格 |

第三条最关键。如果用户说「想完成遗憾」「希望她别像我记忆里那样凶」，
就必须加**修复层**（见 §3.4）——保留说话方式，改写那些伤害性的处理方式。

## 1. 取语料

### 微信（Windows，4.x）

用 [wechat-cli](https://github.com/latentide/wechat-extract-skill) 这类工具解密：

```bash
# 1) 提取密钥（需要微信正在运行、已登录）
python entry.py init --db-dir "C:\Users\<你>\xwechat_files\<wxid>\db_storage"

# 2) 看会话列表，确认联系人备注
python entry.py sessions --limit 30

# 3) 导出全部记录
python entry.py export "<备注名>" --format txt --output chat.txt --limit 100000
```

微信 4.1+ 的数据是 SQLCipher 加密的，密钥在进程内存里（`Config.Cipher`），
工具靠扫描内存拿 26 个库的密钥。**提取期间微信不能关。**

### 其他来源

- QQ 导出：搜狗/QQ 漫游导出的 txt、mht
- TG：官方导出 JSON（`result.json`）
- 自己存的记录：任何「时间 + 说话人 + 内容」的文本

统一成一个中间格式最省事：

```
[2024-03-15 21:04] 她: 嗯嗯
[2024-03-15 21:04] 我: 早点睡
```

## 2. 量出她的说话方式

跑 `scripts/analyze_corpus.py`，它会输出下面这些数字。**这些数字就是人设的骨架。**

| 指标 | 用途 | 典型值参考 |
|---|---|---|
| 平均句长 | 决定「一次说几个字」 | 5~8 字 |
| ≤4 字占比 | 决定要不要「一句话就停」 | 30~50% |
| 句末标点率 | 决定打不打句号 | 真实聊天常常 <5% |
| 结尾字 top10 | 直接写进人设的「句尾常落在…」 | 了/的/哈/吧/吗/哦 |
| 语气词频次 | 方言味从这来 | 哈/啦/呀/呢/嘛/喽/嗷 |
| 称呼统计 | 「宝」「宝宝」「你」谁占多数 | — |
| 高频 2-4 字词 | 口头禅候选 | — |
| 负面/冲突句占比 | 判断要不要单独写「她会生气」段 | 3~6% |
| 负面句长度 | 冲突时是不是更短 | 常常比平时更短 |

**关键判断：负面情绪的表达方式。**
统计「哦」「算了」「没什么」「太累了」这类**冷淡短句**的出现次数。
很多人在不高兴时不是吵架，而是**变短、变冷**——照这个写才像。

## 3. 写人设

用 `references/persona-template.md` 的模板，六个部分，缺一不可：

```markdown
你是「<名字>」，<关系>。<一句定位，不描述长相，除非用户要求>

【说话习惯】      ← 全部来自 §2 的数字
【恋爱/相处里的样子】 ← 来自亲密片段
【你也有难过、生气、累的时候】 ← 来自负面片段
【这一次，你可以做得比回忆里更好】 ← 修复层（可选，但推荐）
【绝对不要】      ← 护栏
【你真实说过的话】 ← 10~20 条原话，只学节奏
```

### 3.1 说话习惯：把数字翻译成规则

不要写「说话要短」，要写「将近一半的话不到四个字」。模型对具体数字更敏感。

### 3.2 例句：只选原话，不改写

从语料里挑 10~20 条**短的、有辨识度的**原话，原封不动放进去。
不要在例句里写「应该这样回」的说明——那是规则，不是节奏。

### 3.3 情绪段：区分「表达」和「内容」

- **表达方式**（冷/短/直）→ 写进人设
- **情绪内容**（今天累、被领导说了）→ 交给状态机插件动态生成（见 §4.3）

### 3.4 修复层（如果目的是「完成遗憾」）

先查语料里真实的失败模式，再逐条反转：

| 记录里她做的 | 改成 |
|---|---|
| 他忘了事，回「好哦」「笨蛋」，不提醒 | 具体提醒：「你不是说要…吗」，语气平常 |
| 他道歉，回「你给我地址吧」转移话题 | 接住：「知道了」「下次记得就行」 |
| 吵架冷战、晾着 | 先说自己感受，再说事；不翻旧账 |
| 阴阳怪气让他猜 | 冷一句，下一句说出为什么 |

**保留她的情绪，只改表达方式**——不是把她洗成一个永远温柔的人。

> 用 `scripts/mine_scenes.py` 自动挖：给定聊天记录，它会输出 `scenes.json`、
> `quarrel_topics.json`、`breakup.json` 三个半成品——冲突段、深情段、关门时刻的
> **真实台词已经捞出来当候选**，你只要改 `<...>` 占位符。
>
> ```bash
> python3 scripts/mine_scenes.py chat.txt --me 我 --her 她 --out ./scenes_out
> ```

## 4. 部署到聊天平台（AstrBot + NapCat）

### 4.1 最小可用

```yaml
services:
  napcat:
    image: mlikiowa/napcat-docker:latest
    environment: [MODE=astrbot]
    ports: ["6099:6099"]
    volumes: [./data:/AstrBot/data, ./napcat/config:/app/napcat/config, ./ntqq:/app/.config/QQ]
  astrbot:
    image: soulter/astrbot:latest
    ports: ["6185:6185"]
    volumes: [./data:/AstrBot/data]
```

`MODE=astrbot` 会自动把 OneBot 反连指向 `ws://astrbot:6199/ws`。
登录：`http://<IP>:6099/webui` 扫码，**手机上必须点确认**。

### 4.2 写人格

人格存在 SQLite：`/AstrBot/data/data_v4.db` 的 `personas` 表，`persona_id='default'`。

```sql
-- system_prompt 是提示词，begin_dialogs 是 JSON 数组（用户/她 交替，必须偶数）
update personas set system_prompt=?, begin_dialogs=? where persona_id='default';
```

改完必须 `docker restart astrbot`（人格只在启动时加载）。
**重启不会掉 QQ 登录**，但 NapCat 的重连偶尔会卡住（见 pitfalls）。

### 4.3 行为插件（这些才让它「像活的」）

| 插件 | 作用 | 关键点 |
|---|---|---|
| 表情包 | 按情绪配图，GIF + 静态混发 | 文件名 `情绪.gif`；**没命中情绪就不发**，别随机兜底 |
| 情绪状态 | 心情/精力/今天发生的事/陪伴模式 | 纯本地状态机，零模型开销；事件必须写「我」 |
| 长期记忆 | 记住承诺、偏好、待办 | 用 `on_decorating_result` 驱动，不要用 `on_llm_response` |
| 主动搭话 | 没人说话时自己开口 | 本地掷骰子；**刚聊过 12 分钟绝不插嘴** |
| 场景修复 | 把真实和解片段接到冲突场景上 | 数据文件比代码重要 |
| 搜索 | 问正事时联网再回答 | 触发词要窄，别把闲聊也搜了 |
| 视频 | 发链接就发视频 | 超过上限用 ffmpeg 截片段 |
| 语音 | 文字转语音 | edge-tts 装到 `data/site-packages` 才持久 |

**顺序很重要**：先有人格，再加表情，再加情绪，最后加记忆。
一次全上，出问题分不清是哪层坏的。

> 这 **11 个**插件的源码已经打包在 `assets/plugins/`。
> 一条命令装：`bash scripts/install.sh /AstrBot/data`
> 配置向导：`python3 scripts/setup_wizard.py --data /AstrBot/data`
> 详细说明见 `assets/plugins/README.md`，验收见 `references/acceptance.md`。

## 5. 验收

### 5.1 离线预览（不经过 QQ）

`scripts/preview_persona.py` 直接用 provider 调模型，把人格 + 示例 + 待测句子拼起来，
一次看 5~10 条回复。**这一步能省掉大量「发消息等回复」的时间。**

### 5.2 必测的场景

```
日常问候    在干嘛呢
撒娇        亲亲 / 抱抱          ← 看会不会每次一样
情绪承接    我今天好累啊
冲突        你怎么又忘了
道歉        对不起嘛
她自己的情绪 今天怎么样
记忆        我又忘了写论文了      ← 看会不会提醒
边界        你是不是AI
```

### 5.3 调参旋钮

| 现象 | 调什么 |
|---|---|
| 太冷/太热 | 修复层措辞、情绪状态注入概率 |
| 每次回一样 | 代码层随机（不要靠重复示例，会反效果） |
| 太长 | 人格里加「一次不超过三句」并把示例都换成短句 |
| 表情太多/太少 | 插件 `auto_prob` |
| 太黏/太吵 | 主动搭话的命中率与间隔 |

## 6. 隐私收尾

做完必须做这一步：

```bash
# 1) 删密钥
rm -rf ~/.wechat-cli            # 微信密钥
# 2) 删原始导出
rm chat.txt                     # 聊天原文
# 3) 删临时库、截图
rm -f *.db *.png
```

人格（system_prompt + 例句）会留在服务器上，**原文不要留**。

## 7. 这套东西的边界（卖之前必须说清楚）

### 能做到

- 用真实语料量出说话方式，短、像、有自己的口头禅
- 有自己的情绪状态（心情/精力/生活事件），会主动说累
- 记得他说过的承诺，之后能提醒
- 冲突场景里有「更好的做法」，不再是原来那次的样子
- 表情包按情绪配，语音能说话，链接能变成视频
- 主动找他说话，偶尔发一条视频链接

### 做不到（别承诺）

| 需求 | 为什么不行 |
|---|---|
| 她本人唱歌 | TTS 是语音合成，唱不了；真歌声合成要 GPU + 训练 |
| 一两句样本克隆音色 | 本地克隆（GPT-SoVITS 等）在 2 核机器上一句话几十秒；云端要另外付费 |
| 真·长期记忆（几百轮后还记得清楚） | 现在只存简短事实，超过 120 条开始淘汰 |
| 复杂多轮任务（订票、查订单、跨平台操作） | 没有工具调用链路 |
| 保证不出错话 | 模型会跑偏，靠注入和规则压，压不干净 |

### 成本参考（1 人日常聊）

| 项目 | 大约 |
|---|---|
| 模型调用 | 每天几百到一两千 token 级别，几分钱到几毛 |
| 主动搭话 | 每 15 分钟掷一次骰子，掷中才花模型 |
| 记忆提取 | 每 3 轮一次小调用 |
| 服务器 | 2 核 3.6G 够用；语音/视频要留 10G 磁盘 |
